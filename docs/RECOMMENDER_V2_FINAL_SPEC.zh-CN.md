# Bustag V2 最终推荐模型规格（交付其他模型实现）

> 状态：设计规格；未据此完成代码、模型训练、NAS 部署或验收。
> 目标环境：NAS + Docker + SQLite + Emby。复刻仓库 PanVivi/bustag；现有 feature/recommender-v2 分支及未合并 PR #1 为代码开发基线。实现前必须重新读取 HEAD，不得覆盖现有有效修复。
> 证据边界：用户在另一 Work 对话调查过 JavDB 页面，但本次提交未取得其完整浏览器报告；下面不虚构具体网站分类 ID、标签全量列表、标注机制或分流域名的有效性。具体站点字段应在实现前附实测记录。

## 0. 总目标与范围冻结

从原 Bustag 的“标签近邻二分类”升级为真正根据用户人工标注学习的个人推荐系统：女优明确喜欢优先，影片类型和网站标签辅助排序；同时从 NAS/Emby 已收藏影片提取有限的辅助兴趣信号，提供【发现新片】和【本地片库推荐】两个入口。标签相近但不符合个人审美的作品不能仅因标签相同就自动被高优先推荐。

保留已有 SQLite 影片与打标、既有爬虫、NAS Docker、现有模型作为对照和可回滚基线。不得用删除重建数据库代替迁移；本期不强制引入 GPU、LLM、视觉审美模型、向量数据库、新消息队列或独立微服务。视觉学习是未来可选项目，本期不得宣称已识别人物外貌。未经单独明确授权不得部署生产 NAS、移动/删除 Emby 视频或修改媒体元数据。

## 1. 用户需求：不可被算法重解释的行为合同

1. 女优状态只有【喜欢、不喜欢、待确认】，默认待确认。用户手动明确设置的三态为真值；模型可以建议人工复核，不能通过一次影片反馈自行更改演员状态；不得增设“特别喜欢、一般喜欢”等等级。
2. 用户明确选择 A：只要出演女优是已明确喜欢状态，该影片即使不符合通常喜爱的题材或玩法，只要该片没有被用户明确标记不喜欢，也应具备优先推荐资格。题材不匹配可以改变优先队列内部排序，不能取消已明确喜欢女优的基本优先资格。可为未知女优保留少量探索位置。
3. 已明确不喜欢的【具体影片】不得反复推荐；该片的负面反馈不能直接改变出演女优的整体喜欢状态。多演员作品的差评也不得平均归因到所有演员。只有在多部独立影片、多个不同场景出现可靠且持续的负面反馈时，模型才可降低特定演员×内容组合的得分，或提示用户手工复核；仍不能擅自覆盖人工演员状态。相同影片的多次标记/不同文件副本不可当作多条独立样本。
4. JavDB 等网站标签只是可能缺失和错误的影片元数据，不是用户喜欢的结论；偏好必须以用户已经完成的人工正负打标为核心学习。NTR、NTS、M男、熟女等仅为用户举例，绝不能写死为专属权重名单或完整标签表。
5. NAS 本地已收藏影片应通过其演员、系列、题材及其他实际标签影响【其他候选影片】的辅助评分，不是只给已收藏作品本身显示一个固定积分。已人工不喜欢的影片即使仍收藏也不能因收藏重新视为喜欢。
6. 双入口共用偏好模型与统一作品 ID：“发现新片”默认排除已收藏、已显式不喜欢及重复作品；“本地推荐”只从 Emby 中当前可播放的作品排序，并能准确跳转对应 Emby 项目。

## 2. 当前代码基线与不能沿用的缺陷

原始仓库的 bustag/model/prepare.py 将不同标签类别的值合并，classifier.py 使用 11 近邻 KNN 二分类，spider/db.py 的 ItemRate 混存 SYSTEM_RATE 预测和 USER_RATE 人工判断，已预测为不喜欢的旧作品可能不再重评分。

现有复刻分支 feature/recommender-v2 已初步实现逻辑回归、带类型前缀的演员/分类/系列特征、连续推荐分数、旧预测重评分、全量人工标签最终训练，但【不代表】本规格所需的女优三态、多来源标签映射、Emby 辅助学习及双入口已完成。现有代码仍可能写 SYSTEM_RATE 到旧表；需迁移到人工真值与系统预测严格分离的结构。既有默认时间衰减不能作用于用户明确喜欢演员的优先规则；是否对历史影片反馈衰减，应通过真实数据实验决定。

检查 Dockerfile、requirements.txt 的安装路径，确保构建后运行的是本复刻仓库修改版代码，不是被依赖条目拉回上游 gxtrobot/bustag@v0.2.1；固定验证过的运行环境，旧 pickle 不得在不兼容依赖升级后盲目反序列化。

## 3. 数据结构合同（表名可调整，语义不可丢）

- work_identity：稳定内部 work_id，规范化番号、必要时的版本/系列区别、去重映射。不同清晰度与重复文件合并到同一个作品，但真正不同的剪辑/特别版不得仅靠标题相似强行合并；不确定匹配进入待确认。
- source_item：每个站点的原始作品 ID/链接、名称、番号、来源与观测时间及解析状态；原始元数据保留，不静默覆盖。
- canonical_tag / source_tag / work_tag：内部标签 ID、类别、网站原始类别/标签 ID 及原文、映射版本、是否人工核实、影片与标签关系及来源。允许缺失、错误和站点冲突；同义标准化后仅形成一个语义特征，来源数量不能直接重复叠分。
- actor / actor_alias / work_actor：稳定演员 ID、各网站原始演员 ID/别名、歧义状态与作品关联；不同人同名不能自动合并。演员偏好使用独立身份特征，不仅依赖通用字符串。
- actor_preference：actor_id、人工三态、设置时间及来源；仅用户明确操作更改，不由训练覆盖。
- explicit_work_feedback：work_id、当前有效人工 like/dislike、确认时间、可追溯变更记录；从旧 USER_RATE 非破坏性迁入。旧 SYSTEM_RATE 是历史系统预测，不是训练真值。
- recommendation_score：work_id、模型/特征/标签映射版本、主模型分数、可选收藏辅助分、队列、最终排序字段、更新时间；允许模型更新后重新评分，不得伪造人工判断。
- library_inventory / media_copy：work_id（不确定时允许为空）、Emby item_id、NAS 媒体路径仅存本地数据库、文件存在/可播放状态、上次同步时间、重复版本关联。Emby 片库数据不得上传公共 GitHub。
- model_manifest / feedback_event：模型工件校验、训练数据版本、算法/参数/指标与人工反馈历史，支持回滚和可解释排障。

兼容迁移：先备份与确认 SQLite WAL 的一致性，再建新表/索引，增量迁入、抽样验证，最后切换读取路径；旧 Item、Tag、ItemTag、ItemRate、LocalItem 先保留。模型文件、配置与 DB 的回滚版本必须互相兼容。

## 4. JavDB 及不同网站标签处理

- 不能假设所有影片都有主题、角色、服装、体型、行为、玩法，也不能把这些用户观察到的类别当作所有影片大类的完整全集。依真实抓取到的【每一部影片】实际出现的分类和标签记录；该分类缺失标记为 unknown，不可转换成用户不喜欢或片中必定不存在。
- 以 (source, source_category_id/name, source_tag_id/name) 保存原始标签；规范化映射须有可审查的别名/语义判断。跨站同名可能不同义、异名可能同义；同义标签合并后只提供一项特征，不因两个站点同时标注就加倍。某站无标签不等于另一站误标；相反标签保留冲突及来源，优先使用用户明确纠错或经过验证的映射。
- 标签类别不是固定得分。类别权重及具体标签权重分别在真实正负人工打标上学习；需要类别归一化、正则化、稀疏标签处理，避免拥有十几个标签的影片天然比两个标签的影片得高分。
- 站点标签不准时提供用户纠错覆盖层，保留原始值便于追踪；标签映射变动须同步重新构造受影响特征并重评分。训练与预测必须使用同一映射版本与编码器。
- JavDB 可作为可替换的数据来源适配器，先附 Work 浏览器核查或新实测的访问日期、真实标签类别与部分不同影片大类的字段样本、缺失案例及限制，再实施真实字段抓取；不承诺未经验证的标签总表、接口、分流域名或后台自动打标机制。抓取失败不删旧数据。

## 5. 模型与排序实现

### 5.1 主模型、特征、学习

先用用户已经实际标记喜欢/不喜欢的作品训练。旧 KNN 为基线；正则化逻辑回归为首个新主模型候选，必要时与调参 KNN、轻量朴素贝叶斯比较，最终模型以同一真实数据上的评估选定，不预设一定获胜。

基础特征：稳定演员 ID、标准化后的具体标签及所属类别、系列；标题和演员×题材/系列×玩法等组合是需通过实验验证的候选特征。对多演员片采用保守且可验证的聚合，不把一次喜欢或不喜欢机械归给每位演员。类别先验允许让演员特征更受重视，但具体权重由真实样本拟合或交叉验证，不能把演员 50%、收藏 0.2 等示意值宣称为最优。

明确演员状态与影片级学习独立：人工喜欢的女优优先资格是排序规则，不随主模型的普通分数、单部差评或训练日期改变；演员×特定类型的负面反馈可以影响对应类型内部排序。不能通过标签相似度声称已经学会了演员的真实外貌审美。未见过演员且只有笼统体型标签时以待确认/探索处理。

输出连续匹配分数。原始 predict_proba 在未校准前显示为“匹配分数”，不能直接标称准确的喜欢概率。推荐阈值和类别/辅助权重必须随真实验证调整；未被人工查看的影片不能作为负样本。

### 5.2 本地收藏辅助模型

对“在 Emby 已拥有、但未人工标注”的每个规范化作品只保留一条弱正向兴趣事件：提取它的稳定演员 ID、系列、可靠标签类别/具体标签，形成个人收藏特征原型或合适的弱监督样本。它应当通过共享特征使【其他作品】得到有限辅助评分，而非给已收藏作品自身统一常数。对批量无筛选下载、低置信度匹配、通用高频标签减权或禁用；不收藏不是负样本。

人工标注与收藏矛盾时以人工标注为准。同片不因 4K、1080p、字幕版或不同 Emby 文件 ID 重复计权；已显式打标的作品不得因为收藏被再作为额外一条正类样本。做“仅人工标签”与“人工标签+收藏辅助”的消融实验；若收藏导致误推增加或召回无收益，辅助权重允许为零。收藏信号参数不提前定死。

### 5.3 候选、队列和最终排序

先处理显式不喜欢具体作品、重复版本及入口候选资格。其余作品分为：
1. actor_first：包含明确喜欢女优的尚未否定作品。即使其他题材不合口味也保留资格；队列内由主模型和可用组合/收藏分排序。
2. general：其余候选按主模型与通过验证的辅助分排序。
3. explore：从待确认/新女优、模型不确定与标签少的作品保留有限探索位置，以发现原算法错误过滤的片。

三类不是给演员设置“特别喜欢”等新状态。actor_first 的优先资格不得被 general 的数十个普通标签累计分数抵消。含显式喜欢与显式不喜欢多位演员的冲突作品进入可配置待确认处理，不强行正负相抵。人工明确不喜欢的单片永不因演员优先而再次被新片推荐。保留旧 SYSTEM_RATE 作品重新评分通道，系统预测不充当真值。

## 6. Emby 接入及两个入口

Emby 只读连接须经用户授权。仅获取必要媒体库范围、Item ID、路径、出演信息、标签、可用的元数据提供者 ID、收藏/播放状态；秘密通过 NAS 私有环境配置注入，严禁上传 GitHub 或泄漏日志。Emby API 失败保留上次成功的快照并标记过期，不把临时离线当作用户删库。首次同步可中断续跑与限流；后续增量更新。严禁自动删除、移动视频或改 Emby 元数据/播放历史。

作品匹配综合已验证外部 ID、规范化番号、必要时文件名/标题；存在歧义就待人工确认，不把不同片强行合并；同一作品多个文件仅形成一次收藏证据。原 Bustag LocalItem 的点击播放次数与 Emby 的实际播放记录必须区分，不能当作同一指标。

【发现新片】默认排除已确认不喜欢、Emby 已拥有、同片副本；按女优优先+模型排序并保留探索位，允许用户打标及查看推荐依据。
【本地片库推荐】只选择当前 Emby 可播放的库内作品，按同一偏好模型排序并准确链接到 Emby 对应 Item；若集合全是收藏片，统一收藏常数对集合内排序不起作用，需靠演员、具体标签、用户反馈与可选经过验证的播放特征排序。

## 7. 训练数据、比较与验收指标

- 启动前统计人工正负样本数量、演员覆盖率、来源标签覆盖/冲突、Emby 可匹配率与重复副本。样本少或类别严重偏斜时明确报告限制，回退女优显式优先+旧模型/保守规则，不虚构模型准确率。
- 按规范化 work_id 分组防止不同站点同片或同片副本跨训练/测试集泄漏；分层并做保留时间段测试，必要时分别评估已见演员和全新演员。禁止未来打标、收藏、映射变更穿越进历史训练数据。
- 同一固定数据拆分对比旧 KNN、已有分支 V2 和最终方案；做演员优先、类别映射、收藏辅助的消融。评估 Precision@K、Recall@K、独立测试的正类召回、人工确认喜欢率、已明确喜欢女优覆盖、误推与漏推案例；注明样本数/正负比例、数据时间、置信区间或波动。仅对有真实标注的样本计算监督指标，未浏览不等于不喜欢。
- 评估完成后使用全部有效显式标签重训最终模型，生成版本化模型+编码器+映射 manifest 单一受控工件；先写临时文件、完整读回核验，再原子切换。训练/重评分不阻塞 Web，也不覆盖用户打标；模型失效、SQLite 写入异常、Emby 不可达时沿用旧可运行模型和数据。
- UI 显示来源可靠的推荐理由、人工三态、标签纠错、重评分/训练状态、双入口；不得把自动标签或模型打分冒充人工真值。

P4：独立隔离环境执行单测、集成与 Docker/SQLite/Emby 冒烟；三次完整独立逻辑审查且无实质阻断后形成可部署版本。任何新增问题需修正并重审；生产切换只在用户另行明确批准后进行，并先备份、保留快速回滚。

必须覆盖的自动/手动用例：
- 明确喜欢女优的一部不喜欢题材作品仍在优先队列；单片差评只排除该片、不改变该女优状态。
- 同类标签的未知演员不能仅凭标签超越人工喜欢演员；多演员冲突不自动抹去显式偏好。
- 多站同义标签不重复加分，缺失类别为 unknown，同名异义不合并，误标可纠正。
- 一片多个版本仅计一次收藏；已收藏但明确不喜欢不得作为正训练样本；收藏特征对其他相似片的加分需实际消融验证。
- 旧系统预测负片重训后可重新评分；Emby 同步失败不删库；新片排除已拥有，本地推荐只列可播放且跳转准确。
- Docker 镜像实际加载本 fork 新代码；旧用户标注、媒体文件完整保留；新模型失败能恢复前一个镜像、数据库、模型及配置组合。
